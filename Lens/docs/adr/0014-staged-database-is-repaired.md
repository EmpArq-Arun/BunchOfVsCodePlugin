# ADR 0014 — The staged database is repaired, not copied

Status: accepted (1.0.7) · found by a real project

## Context

With the git problem resolved, clang-uml reached the translation units and failed
on the database itself:

    [ERROR] no such file or directory: '# compile_flags.txt — generated by Embedded clangd Generator'
    [ERROR] no such file or directory: '# Re-run "Embedded: Generate clangd Config Files" to refresh.'
    [FATAL] BuzzerTask.h:11: 'stdbool.h' file not found

Two unrelated defects wearing one error report.

**Comment lines as arguments.** A database generated from a `compile_flags.txt`
had carried the file's comment lines into `arguments`. A compiler treats those as
input filenames, so the report reads like missing source files. Reproduced
directly: `clang '# a comment' App.c` gives exactly `no such file or directory`.

**A missing builtin header.** `stdbool.h` is not a system header — it lives in
clang's own resource directory. clang-uml bundles its own LLVM and on Windows
does not always locate it, so every C translation unit fails on the first
`#include <stdbool.h>`.

## Decision

**Always rewrite the staged database rather than copying it.**

clang-uml reads the compilation database itself, so Lens's own `sanitiseFlags` —
which already handled this for the AST and layout lenses — never applied. The
staging step introduced in ADR 0010 was a byte copy. It now parses, repairs and
re-serialises, which makes it the single point where anything wrong with an input
Lens does not control can be corrected.

Two repairs, both applied unconditionally:

- Arguments that are not arguments are dropped: anything starting with `#` or
  `//`, and anything blank. A comment is never a flag.
- `-isystem <resource-dir>/include` is inserted, with the directory obtained by
  asking the configured `lens.clang.path` for `-print-resource-dir`. That resolves
  builtin headers without assuming anything about how clang-uml was installed.

Extra flags go immediately after the compiler, before the project's own flags, so
a project can still override them.

The comment stripping is shared with `sanitiseFlags`, since the same malformed
database also feeds the Rosetta and Layout lenses.

## Verification

Reproduced against real clang-uml 0.6.3 with a deliberately polluted database.
Before staging: two `no such file or directory` errors plus a fatal missing
header. After staging: clean run, 14 elements. Repeated for a C translation unit
including `stdbool.h` and `stdint.h` with `--target=arm-none-eabi`, which also
now succeeds.

## Note

This is the fourth consecutive failure in this lens whose real cause was upstream
of the C++ — a filename, a working directory, a git revision, and now the
contents of a generated file. The parsing and analysis have needed no changes at
all. Worth remembering when weighing where the remaining risk in this project
actually sits.
